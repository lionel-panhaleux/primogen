- **`vtes_rules_case` takes no card from a game word or a common noun** [M:rules]: a word the question uses as a word of the game names no card. Where a part of a name is weighed by a single word, that word is no word the rulebook uses outside the card's name ("the Death of my vampire"). Titles and traits printed in card text, like Seraph, count as game terms. Players' shorthand that no source lists ("NRA", "hunter") is kept in an authored list in `knowledge/`, separate from the game terms. Done when "Is that NRA?", "Is the Hunter's action blocked?", "Can the Seraph's bleed be bounced?" and "Is the Death of my vampire final?", asked without cards, find no card, while the 2026-11-12 entries on Tangle Atropos' Hand and Concealed Weapon still find Tangle Atropos' Hand and .44 Magnum. Docs: product.md (the `vtes_rules_case` row), provenance.md (the authored list), principles.md ("Knowledge files", authored here).
- **`vtes_rules_case` brings the rules directors' posts no ruling cites** [M:rules]: where no ruling names two of the question's cards together, the pack adds the rulings archive's posts by a sitting rules director naming both, the closest to the question first, each with its author's standing and link, within the bound. The rulings database misses some of what the rules directors settled (Foreshadowing Destruction with Conditioning: Ankha's "About bleed modifiers"); the tools work around it until a later pass over the database (owner, 2026-11-12). Done when the 2026-11-12 Foreshadowing Destruction entry's pack holds that thread and its known miss is gone from the evidence tests. Docs: product.md (the `vtes_rules_case` row; "Connecting", a local install fetching the archive at its first `vtes_rules_case` call; "Evaluation", the known misses).
- **The rulings' rulebook links point to archon.vekn.net**: the `RBK` references of `vtes-rulings` (`references.yaml`) and the rulebook links the rulings site writes and offers move from `vekn.net/rulebook` anchors to the ids of `archon.vekn.net/help/rules`, their labels unchanged (a ruling's id hashes its text, labels included), each done in its own repository through its own harness. Done when every `RBK` reference in `references.yaml` links an id archon's renderer gives the rules page, and `primogen build` reports no rulebook reference unanswered. Docs: sources.md (the vekn.net row, "The rulings chain").
- **`mcp.krcg.org` lists the KRCG stack for developers and their agents**: the root and `/llms.txt` serve one catalog, authored in `knowledge/`, of the public services (the MCP endpoint and the published bundle, `static.krcg.org`, `api.krcg.org`, the rulings site's read API, the archive's bulk file, the engine, Archon's API and its token rule, the upstream repositories), each linking its own live specification; the status page moves to `/status`. Done when `curl https://mcp.krcg.org/` and `/llms.txt` return the catalog, every URL in it answers at each refresh (a dead one is a warning on the status page), and a fresh agent given only `https://mcp.krcg.org` finds the card data and the MCP endpoint. Docs: product.md "Connecting" (authored, linking each live specification, links checked at every refresh, replaces "generated from the live specifications"), operations.md, provenance.md, roadmap.md (the `llms.txt` item leaves "Later").
